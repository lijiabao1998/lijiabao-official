## 先保留位置，讓後面的文字有地方停

文章已經可以閱讀，主圖一出現，原本正在看的段落卻往下跳。這種情況不一定要靠把圖片壓得更小來處理：瀏覽器若一開始不知道圖片應占多少高度，即使下載很快，也可能在排版時重新騰出空間。圖片尺寸設定處理的是這段等待中的版面，和載入優先權各有用途。

![螢幕上的抽象文章版面預先保留主圖矩形區域，桌面擺放開發工作用品。](../../../assets/articles/image-dimensions-aspect-ratio-layout-shift/zh-Hant-hero.webp)

假設一張圖片的比例是三比二，版面讓它顯示為三百個 CSS 像素寬，相應高度就是兩百。這只是比例計算的示例，不是某個正式網站的量測結果。瀏覽器若先知道這個比例，便能在圖片資料到達前，替它安排相應空間。

web.dev 的 CLS 指南將未設定尺寸的圖片列為常見原因。處理重點是讓初次排版有可靠依據，而不是等圖片出現後，再用腳本把內容推回看起來正確的位置。讀者正在點擊的連結或閱讀中的句子，應盡量在載入過程保有穩定位置。

## HTML 寬高可以提供比例，不必鎖死手機尺寸

原生圖片的 `width` 與 `height` 屬性，能讓瀏覽器提早計算比例。屬性中的數字不寫 `px` 單位；實際顯示大小仍可由樣式控制。例如一張來源為一千兩百乘八百的圖片，可以保留對應寬高，再以 CSS 設定 `max-width: 100%` 與 `height: auto`，配合容器縮放。

因此，響應式設計不必為了讓圖片縮小，就把這兩個屬性刪掉。要留意的是比例是否正確，以及其他樣式有沒有另外指定固定高度。圖片看起來正常，仍值得檢查瀏覽器第一次排版採用的尺寸，而不只看下載完成後的結果。

## aspect-ratio 要與寬高的實際控制方式一起看

CSS 的 `aspect-ratio` 提供盒子的偏好比例，適合用來安排有明確比例的媒體區域。MDN 提醒，至少一個方向的尺寸需要由自動計算決定；若寬高都已經被固定，不能期待再加一行比例設定就改變那個盒子的大小。

圖片還有自身的原始比例。使用含有 `auto` 的比例設定時，載入前的暫用比例，與取得圖片後採用的比例可能不同。若兩者不一致，仍可能發生調整。應先決定要保留原圖比例，還是刻意使用固定裁切框，再讓 HTML、樣式及實際資產的資訊一致。

## 手機換了裁切版本，也要換相應的占位方式

同一張構圖縮成不同解析度，和手機改用另一種直式裁切，是兩種需求。前者若比例一致，通常較容易共用比例資訊；後者若比例改變，卻還沿用桌機橫圖的占位高度，圖片出現時便可能需要重新調整。

檢查 `picture`、`source`、`srcset` 與斷點樣式時，要看瀏覽器實際選中的版本。不能只驗證預設 `src` 的檔案尺寸，就認定每個畫面寬度都有正確空間。若設計是固定圖片框，則要確認不同版本都在同一框內呈現，而不是載入後才改變外框高度。

## 固定圖片框，仍要驗收內容是否被裁錯

版面可以先保留固定比例，再透過 `object-fit` 控制圖片如何放進去。這能讓卡片外形保持一致，但不會替編輯判斷重要內容是否完整。主體、圖中文字或圖片邊緣的資訊，可能因裁切而消失。

所以，畫面不跳動與圖片好閱讀應分別看。若文章需要讀到整張圖的細節，保留自然比例可能較合適；若是卡片縮圖，可以安排固定框，但應檢查重要主體的位置。不要只為了得到整齊格線，就把對讀者有用的內容裁掉。

## 用載入過程找原因，分開理解測試與訪客資料

觀察時可從沒有圖片快取的條件開始，放慢網路並觀看段落如何排開，再捲動到頁面下方的圖片。這樣比較容易看見占位不足的地方。網路與裝置條件要留下來，方便對照同一項調整，而不是把兩次不同條件的分數直接相減。

載入測試只看到訪問過程的一部分。web.dev 對實驗室與實際訪客資料的說明，也指出捲動後出現的延遲內容可能帶來差異。主圖穩定了，頁面仍可能受字型、嵌入內容或後續插入的區塊影響；整頁的觀察範圍需要跟著讀者的操作延伸。

## 發布後讀回輸出，確認比例資訊確實送到了頁面

原始碼中的圖片元件，可能在建置時被轉換成另一段 HTML。驗收時讀回正式回應，確認寬高或比例資訊存在，再對照實際選取的圖片與顯示框。只在編輯器裡看見設定，還不足以判斷正式頁面已採用同一條件。

可以留下來源尺寸、預期顯示方式與問題發生的位置，讓修正對準特定元件。若發現是手機裁切造成的比例落差，就處理該斷點；若是後續插入區塊推開內容，就不要繼續把問題全歸給圖片壓縮。每次修正都應對應觀察到的原因。

讓瀏覽器提早知道圖片的空間，是穩定版面的基礎。把資產比例、響應式排版與載入過程連起來檢查，才能同時照顧圖片呈現與讀者正在閱讀的位置。
